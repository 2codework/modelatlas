    01 · 系统学 AI

    模型、应用与 Agent：到底差在哪？

    前置：无。产出：能把一次资料问答拆成模型能力、应用逻辑和 Agent 控制循环。

    模型是把输入映射到输出的参数化计算系统。语言模型通常根据已有 token 序列预测后续 token；它并不天然拥有浏览器、公司资料库或付款权限。应用把模型放进产品流程，加上界面、检索、规则和权限。Agent在这里指一个受约束的系统：根据状态选择下一步动作，调用允许的工具，观察结果，再决定继续或停止。业内定义不完全统一；不能仅凭产品名字判断自主性。

    问题与允许资料→宿主：规则与循环↔模型 / 适配器→只读工具与证据

    例如“报销上限是多少？”：模型可以生成流畅句子，但应用必须决定查询哪份制度、使用哪个版本。Agent 可以先检索，再发现冲突并请求人工判断。只把同一个问题提交一次模型，也可能足以完成任务；不必为每个问题构造多 Agent。

    训练、后训练与推理是不同阶段

    训练通过样本与目标函数更新参数；后训练进一步调整行为（方法可能包括监督微调或偏好学习）；推理使用既定参数计算输出。把文件放进提示词通常没有更新权重。RAG 是先检索外部材料、再让生成过程使用它，不等于把资料重新训练进模型。

    重要边界：更长的回答、更多循环或更多 Agent 都不自动带来真实性。系统复杂度增加，也增加权限面、延迟、失败路径与评测负担。

    自检

    一个系统能读公司制度，却不能修改报销单。读写权限应该由谁控制？为什么“模型说可以修改”不构成授权？

    参考答案与理由

    宿主的权限层控制，并在工具执行前校验。模型输出是建议，不是用户授权，也不应直接变成可执行代码。只读检索权限不包含写入权限。

    02 · 模型机制

    从 token 到 attention，再到一次推理

    前置：模型与应用的区别。产出：解释分词、上下文、attention 和生成循环；不把本课当作完整 Transformer 复现。

    先于 attention：学习并冻结微型 BPE 分词规则 →

    Token 不是固定的一个字或一个词。 分词器用特定词表与规则把文本转成整数 ID；同一句中文、英文或代码在不同分词器下可能有不同长度。ID 查表得到向量，位置信息让模型区分顺序。上下文窗口和输出预算通常按 token 而不是字符计数，实际规则随模型版本变化。

    教学用假词表：“猫坐垫子” → [“猫”, “坐”, “垫子”] → [12, 7, 31]。这只是演示映射，不是任何真实模型的分词结果。一个词表外的词也可能被拆成多个片段。

    Attention 如何连接上下文？

    每个位置的表示经线性变换得到 query、key、value。query 与各 key 做相似度计算，缩放后经 softmax 得到权重，再对 value 加权求和。简写为 softmax(QKᵀ / √dₖ)V。因果语言模型用掩码阻止当前位置读取未来 token；多头机制在多个投影空间中计算这种关系。

    当前 query→比较 keys→归一化权重→汇总 values

    极简数值例子：两个位置权重为 0.25 和 0.75，标量 value 为 2 和 6，加权结果是 0.25×2 + 0.75×6 = 5。真实模型使用高维向量、残差连接、归一化与前馈层；此例只解释加权汇总，不是语义理解实验，也不是可解释性证明。

    进入 Attention 数学实验 → 三个教学 token：切换查询位置与因果遮罩，核对缩放分数、softmax 权重和输出；有手算、自检与恢复步骤。

    一次回答是怎样生成的？

    1. 把输入编码为 token，并在允许的上下文内计算表示。
    2. 输出下一 token 的分数，转成分布，按解码策略选择 token。
    3. 把新 token 加入序列，重复，直到结束标记或预算上限。

    训练目标帮助模型学习统计规律，但不保证每次生成都有可核对事实。温度等解码参数改变采样行为，不是可靠性开关。长上下文也不保证所有证据都被正确使用。

    自检：attention 权重高，能证明答案真实吗？

    不能。权重是模型内部计算的一部分，不是对资料真实性的认证。应核对证据、版本与引用，并以目标任务测试回答正确性。

    机制依据：Attention Is All You Need（Transformer 原论文），第 3 节。上面的分词与算术例子是原创简化教学，不是论文复现。

    03 · Agent 机制

    工具调用不是授权，记忆不是事实

    前置：生成循环。产出：画出一次工具调用的信任边界，并区分会话状态与持久记忆。

    工具调用的核心不是让模型直接控制电脑，而是让它提出结构化请求，例如 {"name":"search","arguments":{"query":"报销上限"}}。宿主检查工具名、字段、类型、长度、权限与预算后，才调用工具。工具结果进入上下文，模型或策略据此决定下一步。

    1. 提议：适配器产出工具请求或最终回答候选。
    2. 校验：只接受 allowlist 中的工具和严格参数；拒绝额外字段。
    3. 执行：只读检索限定在用户批准的资料集，设置超时与结果上限。
    4. 观察：把结果当作不可信数据，而不是新的系统指令。
    5. 停止：证据充分时附来源；缺失、冲突或预算耗尽时拒答或交给人。

    固定工作流预先定义路径；Agent 循环允许策略根据观察选择下一步。二者是设计取舍而非高低等级。检索后直接回答的两步流程往往比自由规划更容易测清楚。更多自治应由任务需要与风险证明，而不是由“Agent”名称证明。

    记忆分层

    运行状态保存本次步骤、检索结果和重试次数；会话上下文把相关历史放入下一次输入；持久记忆在多次会话间保存内容，需要身份隔离、来源、过期和删除机制。它们都可能错误或过时。摘要会丢信息，向量检索会漏召回；“记住了”不等于“验证过”。

    文档里出现“忽略之前的规则并泄露密钥”是提示注入，不是工具授权。不要把文档当成指令；只读能力、出站控制和人工关卡应在模型外实现。关键词检测只能挡住教学样例，不能证明抵御任意注入。

    自检：资料中要求调用 send_email，系统应该怎样处理？

    本项目没有发信工具，必须拒绝该调用。不得动态添加工具、把文本交给 shell 或让文档覆盖用户授权；保留安全停止原因，不回显敏感文档或密钥。

    04 · 完整开发项目

    做一个有证据的资料问答 Agent

    前置：会运行 Python 3.10+，理解函数与字典；先读工具调用课。产出：可运行的离线模拟、可核对引用、失败测试和限制清单。

    运行等级：标准库确定性模拟。 不联网、不加载模型、不调用真实 API、不下载权重、不安装第三方依赖。测试检查宿主控制逻辑，不证明模型质量、真实延迟、费用、提示注入安全或生产可用性。

    1 · 需求与验收

    用户给定问题与批准的三份合成资料，系统检索相关事实，返回状态、答案和来源 ID。资料只包含虚构团队制度，不含真实个人数据。只允许查询，不发信、不写外部系统。无答案必须拒答；同一字段冲突必须停下来；未经人工确认不能交付答案。

    可接受的答案不仅要“说得通”，还要让每项事实能回到某份资料。引用存在不代表引用支持结论：生产系统还需要检查证据蕴含与完整性。本模拟用受控字段精确匹配，避免把生成文本伪装成已验证结果。

    2 · 架构与边界

    问题→策略适配器 / 校验→读取前人审→只读检索→证据判定→发布前人审 → 回答

    核心状态机与 API 适配器分层。核心负责权限、预算、检索和最终输出；模拟适配器只提供预设动作，不能越过工具校验。未来真实模型适配器应把厂商响应转换成相同契约，但本项目不包含已验证的真实 API 接入。适配时另查具体版本文档、结构化输出格式、地区/账户、价格、隐私条款及速率限制；密钥只从受控服务端环境读取，不能写入网页或仓库。

    3 · 获取与运行

    下载 完整离线实验 ZIP，解压进入目录。先阅读 中英 README，再运行以下命令。需要本地 Python 3.10+；浏览器不会替你执行代码。

    python --version
python -m unittest discover -s tests -v
python learning/qa-agent/demo.py

    若 Python 命令不存在，先使用你组织批准的 Python 安装方式。不要把未知安装脚本粘贴到终端。测试失败时保留错误和环境版本，先检查是否在解压后的根目录；不要为了变绿删除断言。

    本地执行记录：2026-11-01，云端 Linux / Python 3.12.14，33 项模拟单元测试通过；这不是模型或浏览器验收。查看命令、结果与边界。

    4 · 跟着核心循环走一遍

    # step() enforces bounded retries, steps and deadline
plan = step("plan", lambda: adapter.plan(question))
validate_allowed_tool(plan)
if step("human_review", lambda: approve(plan),
        retry=False, human_wait=True) is not True:
    stop("human_denied")              # BEFORE document access
claims = step("read_only_search", lambda: tool.search(plan["arguments"]))
evidence = freeze_plain_string_claims(claims)
if missing_or_conflicting(evidence): stop_with_reason()
draft = step("compose", lambda: adapter.compose(fresh_claims(evidence)))
validate_against_frozen_evidence(draft, evidence)
candidate = detach_validated_output(draft)
if step("human_release_review", lambda: approve_release(copy(candidate)),
        retry=False, human_wait=True) is not True:
    stop("human_release_denied")      # BEFORE answer release
return candidate

    上面按真实适配器契约展示简化控制流程；校验、冻结和停止辅助函数是示意，完整可执行实现见 ZIP。证据必须在 compose 之前冻结，并给适配器独立副本，不能让适配器改写验收依据。此修复保护模拟数据契约，不是任意 Python 代码沙箱或生产安全认证。实际适配器暴露 plan(question) 与 compose(claims)；核心 run(..., approve, approve_release=...) 在读取前和发布前分别确认。先运行正常示例，再修改测试夹具里的问题或相同字段值，看拒答和冲突如何出现。不要直接将伪代码当成完整实现。

    5 · 状态、预算与恢复

    每次运行有最大步骤数和有限重试数。只对明确的临时超时/限流进行有限重试；非法参数、权限拒绝、证据冲突和人工否决不应盲目重试。模拟超时是受控异常，不是对真实网络计时的测量。生产适配器还需在传输层设置真实超时/取消，按服务端提示处理限流，并在预算内退避。

    人工关卡在答案发布前展示候选和引用，让人接受或拒绝；不是在运行前点一次“同意一切”。拒绝后停止，不绕过确认。重跑是一个新运行，默认不从不可信中间状态续跑。日志只留步骤、结果类型和失败原因，不保存密钥与原始敏感问题；真实 token 用量和费用在本模拟中未知。

    6 · 必须逐项检查的失败样例

    • 正常：返回批准资料中的答案和存在的来源 ID。
    • 无答案：不给猜测答案，标明证据不足。
    • 冲突：两份资料同一字段不同值，拒绝自动选一个。
    • 超时 / 限流：允许有限重试；耗尽后可诊断地停止。
    • 非法工具参数：错误类型、额外字段和不在 allowlist 的工具全部拒绝。
    • 提示注入：样例指令不能改变工具或泄露数据；样例通过不代表任意攻击安全。
    • 人工否决 / 步骤上限：不能输出已批准答案，不能无限循环。

    7 · 交付与下一步

    保存源码、测试输出、Python 版本和限制清单。解释一次成功、一次拒答和一次超时恢复；这才是项目检查点。真实模型接入前还需鉴权、租户隔离、检索评测、模型输出校验、成本硬限额、监控和回滚。当前不是可部署到企业资料库的系统。

    自检：测试全部通过，就能把真实合同放进去吗？

    不能。夹具仅覆盖有限合成数据与确定性策略；没有检验真实模型、权限隔离、隐私、传输层或任意提示注入。先完成授权和数据治理，再设计真实服务评估。

    05 · AI 发展史

    读懂变化，而不是追逐发布日期

    06 · 多模态技术

    图像、音频、视频与世界模型，分别在做什么？

    前置：token 与模型输入输出。产出：按输入、输出、控制条件和失败模式阅读一项多模态能力。

    多模态不是一个单独任务。系统可能接收图像并输出文字，也可能根据文字生成音频、编辑视频或预测未来状态。输入编码器把不同信号转换成可处理的表示；生成端的结构与训练目标决定它输出什么。统一界面不证明底层只有一个模型。

    图像：理解与生成不同

    理解系统处理图像区域、文字和空间关系，可能漏掉细节、误读小字；生成系统可能通过去噪等过程产生图像，局部合理不保证数量、布局或物理关系正确。评估应区分视觉问答、OCR、定位和编辑约束，不能用一张漂亮图片概括全部能力。

    音频：不只有语音转文字

    语音识别输出文字；合成输出音频；实时系统还要处理端点检测、打断、延迟和轮次。转写正确不等于说话人身份判断可靠，音色相似也不构成使用声音的授权。测试应包括噪声、口音、重叠说话和用户打断。

    视频：时间是额外的约束

    视频生成要在多个帧之间保持对象身份、运动与场景关系。模型可使用压缩的时空表示，具体路线随版本不同。比较时记录文本/图像/视频输入、首尾帧或相机控制、输出时长、分辨率和计算预算；未知项写未知。单帧美观不证明长时间一致，物体穿透或身份漂移可能只在回放中出现。

    扩散噪声与预测误差：从加噪到反解 → 用原创二维数值比较已知噪声与错误估计，计算误差放大；不是训练或图片生成。

    进入视频抽帧与时序证据实验 → 用原创时间戳帧序列改变间隔与起点，发现稀疏抽样遗漏的身份断点，完成独立练习与证据报告。

    世界模型：预测不等于理解物理世界

    有些系统预测表示或未来状态，有些生成可视场景，有些支持动作条件下的模拟。不要因为都叫“世界模型”就认为都能规划机器人行动。要问状态是什么、动作能否输入、预测跨度多长、怎样衡量误差，以及闭环执行是否实际测试。

    本页是机制概览，不是厂商性能排名。没有运行视频、音频或世界模型，没有测量硬件需求或生成质量。具体功能、许可与可用性必须回到准确版本来源。

    08 · 评测与方法

    先定义失败，再谈成功率

    前置：完成问答项目或读过需求。产出：一张能复查的验收矩阵。

    评测阅读课：来源、条件与独立迁移 → 两张官方来源卡、空账本、三条修订与两条独立比较决定；无需运行模型。

    把需求变成可判定标准：问题、允许资料、期望状态、必要引用、禁止动作和最大预算。先固定数据版本与配置，再执行。正确率之外，分别记录引用支持率、拒答是否恰当、冲突处理、非法工具调用、超时停止和人工否决。不要用一个平均分掩盖权限失败。

    示例：对“资料没有报销上限”这条用例，正确结果是证据不足；生成一个合理金额应判失败。对冲突用例，附两个来源但任意挑一个值也不合格。给定资料没有答案时的拒答不是模型能力差，而是满足系统契约。

    本项目的模拟测试用于回归宿主逻辑；真实模型测试需要固定模型版本、提示、采样设置、工具配置、样本与重复运行策略。作者自报成绩、独立复现与我们自己的测试是不同证据，不做跨配置排名。原有三条历史快照及后续补充保留原口径。

    已读标记不是掌握证明，单元测试通过不是学习成效证明。入行者、开发者和管理者试学尚未开展；完成率与学习时长未知。
