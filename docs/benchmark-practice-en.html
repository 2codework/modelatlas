Goal and limits

Deliver an evaluation-reading ledger, corrected claims C1–C3, at least two unknowns, and two independent transfer decisions with manual review. Original three-claim exercise: editor estimate 15–20 minutes; transfer takes additional time using the supplied cards, not observed completion time. Opening external sources takes extra time.

Use paper or a local text editor. No account, installation, key, model download or payment is needed. This page does not save your work or grade it automatically. The lesson is readable without JavaScript.

Read evidence; do not run benchmarks.

We have not run these benchmarks or independently reproduced them. Website checks do not demonstrate model performance. This lesson does not ask you to follow installation, download or API instructions in the source.

Benchmark
A set of tasks and scoring procedures, not a total score for every real job.
Harness
The program that prepares inputs, calls a model and scores outputs. Its version and settings matter.
Judge
Another model that scores outputs. Its version is an evaluation condition.
CoT
Prompts or processes associated with reasoning or thinking modes. Different modes do not imply equal conditions.
Independent reproduction
Another party actually runs an experiment and leaves inspectable process and results. Reading a report does not qualify.

3. Repair three claims

These are human-authored claims to examine, not actual model outputs. Write supported / unsupported / insufficient evidence and your reasons before opening answers. Labels may differ, but evidence scope cannot expand.

C1 · “The publisher corrected results and released code, so this site has independently tested and confirmed them.”

After your attempt: C1 reference

Unsupported. A supports the publisher's correction and code announcement, not an execution by this site. Repair: the publisher announced corrections on 2025-06-15; our editor read the notice on 2026-10-31, without independent reproduction.

C2 · “RISE defaults to 2.0, so the ordinary Results must use 2.0 and the 1.5 heading is definitely wrong.”

After your attempt: C2 reference

Insufficient evidence. B contains differently scoped labels. Neither a default nor a heading determines every run. Record 2.0 and 1.5 separately; request the corresponding revision, configuration and logs. Do not declare an error or infer a performance effect.

C3 · “A higher score on a benchmark with the same name proves the model is stronger under identical conditions.”

After your attempt: C3 reference

Insufficient evidence. No complete controlled comparison is supplied. Check model snapshot, data revision/subset, harness, prompt/mode, judge, generation settings, budget and metric. Defer direct comparison until conditions are established. Even a comparable result remains limited to that evaluation, not every job.

References are editorial reasoning, not new experiments or official conclusions. One correction does not discredit every other result. Unknown does not mean zero or prove the opposite claim.

4. Independent transfer: same task, same conditions?

Set aside the BAGEL answers. These original fictional cards contain no real vendor, execution logs or scores. IDs and versions are paper-exercise labels; do not add them to a model catalog.

T-A

Teaching model Cedar-r1; teaching data LedgerQA-v1 / Full (100 items); harness-h1; prompt p1; one output; exact-match accuracy; fictional environment e1. These are stipulated fields, not execution evidence.

T-B

All other stipulated fields match T-A, but the subset is LedgerQA-v1 / Hard (20 items). No scores or raw outputs are supplied.

T-C

LedgerQA-v1 / Full (100 items), with prompt, output count, metric and environment as in T-A. The model is only the rolling alias Cedar-latest, exact snapshot unknown; harness version unknown. No scores or raw outputs are supplied.

Independently decide: can T-A versus T-B support a same-condition model ranking? Are T-A and T-C confirmed to use identical conditions? For each, write a decision, supporting card fields, missing evidence and what to defer. Finish with two non-ranking sentences. Matching stipulated fields would not prove that a real experiment ran.

After your attempt: T-A / T-B reference

No same-condition model ranking is supported. Full versus Hard and 100 versus 20 items are known differences; do not merge them into one test. The stated model is even the same. Align the dataset revision, subset, item scope and aggregation, then request corresponding outputs and run records. The cards reveal a condition difference, not performance.

After your attempt: T-A / T-C reference

Whether conditions match remains unknown. Full does not resolve the unpinned Cedar-latest snapshot or missing harness version. Request the alias-to-revision mapping for that run, program commit, configuration and outputs. Do not copy T-A versions into the gaps. Defer comparison; C is not established as better, worse or equivalent.

After your attempt: download references and transfer review

Transfer review: cite concrete fields for both decisions; distinguish known difference from unknown equivalence; name missing evidence and a deferral action for each; invent no score, independent reproduction or execution log. Meeting all four completes this manual exercise check, not a mastery certification.

5. Review and stop

Also deliver the T-A/T-B and T-A/T-C independent decisions and complete the four-part manual transfer review.

  • Both A and B have a source role and section locator. Keep announcement dates, editor dates and your actual reading dates separate.
  • Separate defaults from result labels. Keep unpinned versions and at least two unknowns without guesses.
  • None of the three repairs promotes an author report into independent testing or a ranking.
  • A 3–5 sentence conclusion states what is supported, what is not, and which evidence is missing. A person reviews each item.

Stop when: the ledger, C1–C3 answers, qualified conclusion, two transfer decisions and four-part transfer review are complete. If sources are inaccessible, versions unclear or logs missing, leave pending. Do not bypass access restrictions, download models, enter keys or demand experiment results just to finish.

For real selection, separately establish tasks, budget, authority and a reproducible plan. This exercise teaches evidence reading; it does not select a model.
