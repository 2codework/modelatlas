读懂实时音频

四个问题，分别核验；“实时 / 全双工”不是所有能力的通行证。

01

传输层

数据怎样来回传？

双向流式传输 ≠ 语音对话

Voxtral Realtime 2602：音频输入 → 转写文字输出

可以边收音频边回文字；不生成语音回答。

查：协议方向、消息类型、流式输入与输出。

02

模型能力

输入、输出是什么？

上下文语音生成 ≠ 完整对话产品

CSM 1B：文本 + 音频上下文 → 音频

不等于 Sesame 完整对话产品。

开放 1B 权重的实时双工会话：已核资料未证明。

查：精确模型 ID；未知不写成“不支持”。

03

时延口径

这个数字测了什么？

目标 / 配置延迟 ≠ 真实端到端时延

Voxtral 模型卡推荐配置：480 ms。

这不是本项目实测值，也不是每位用户的体验保证。

实测另记起止点、计算 / 排队 / 网络条件。

04

使用条件

我能怎样使用它？

模型 ≠ 服务 ≠ 产品；开放 ≠ 免条件

CSM 1B：HF 门控；依赖模型访问与条款另核。

分别核验权重、代码、依赖许可和算力条件。

托管 API 另查账号、地区、额度；本项目未验证。

动手核对：挑一个模型，逐项写下“结论 + source_id + 核查日期”。

缺证据就标未知；不要用演示体验替代开放权重的能力或性能。
